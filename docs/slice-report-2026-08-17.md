# body-measure 개발 보고서 — Slice 0~5 전 과정

작성일: 2026-08-17 · 대상: Maß-DPP / 3D 바디스캐너 선행 소프트웨어
저장소: `ITA/body-measure` · 최종 상태: **테스트 46개 전부 통과, 6종 치수 측정 + 3중 검증 체계 가동**

## 0. 왜 이 프로젝트인가

3D 바디스캐너(VITRONIC BodyLoop 유력)는 조달 절차 중이라 도착까지 수 주~수 개월.
그동안 "스캐너가 준 3D 메시 → 셔츠 치수 6종"을 뽑는 측정 파이프라인을 먼저 만들고,
공개 데이터셋을 스캐너 출력의 대역으로 세워 검증까지 마쳐 두는 것이 목표였다.

**계획 단계에서 가장 중요했던 결정은 검증 주장의 경계선이었다:**

> 스캐너 도착 전에는 측정 파이프라인의 **구현 정확성·재현 가능성·강건성**을 검증하고,
> 장비 도착 후 **실제 계측 정확도와 반복성**을 검증한다.

ISO 20685-1은 실피험자 + 숙련 측정자의 수동 측정 + 통계 분석을 전제로 하는 평가
프로토콜이므로, 합성 메시나 데이터셋 비교로 ISO 적합성을 주장하지 않는다. 모든
수치는 6개 카테고리(analytic_correctness / synthetic_agreement / numerical_robustness /
dataset_agreement / scan_repeatability / measurement_accuracy) 중 하나로 라벨링된다.
이 프레임은 초기 계획 리뷰에서 "합성 메시로 ISO 적합성을 검증한다"는 과잉 주장을
지적받고 수정한 결과물이다.

## Slice 0 — 정의 고정, 계약, 해석적 프리미티브

**한 일**
- `measurement-spec.v1.yaml`: 치수 6종을 이름이 아니라 **정의**(ISO 8559-1 기반)·경유점·
  자세·알려진 편차 단위로 고정. 코드가 아니라 spec이 계약이다.
- `NormalizedBodySurface` 어댑터 계약: 모든 입력(데이터셋·일반 파일·미래의 스캐너)은
  mm/Y-up/바닥0으로 정규화된 후에만 측정 코어에 진입. **단위는 절대 추측하지 않음**
  (어댑터 메타데이터 → CLI 명시 → 실패).
- 평면 슬라이싱 + 몸통 루프 선택(축 포함 → 면적 → 최근접 폴백 → null) + 둘레 측정
  (raw 윤곽 + convex hull 병기, hull ≤ raw).
- 해석적 정답 테스트: 원기둥 2πr(내접다각형과는 소수점까지 일치), 타원 vs Ramanujan,
  **2-원기둥 씬**(더 큰 외부 실린더가 있어도 축 기준으로 몸통 선택 — "가장 큰 루프"
  실수를 잡는 회귀 장치).

**우여곡절**
- trimesh의 `Path3D.discrete`가 **열린 단면에서 빈 리스트를 반환**하는 것을 발견.
  구멍 난 메시를 "보고"해야 하는 우리 요구와 충돌 → `mesh_plane` 세그먼트를 직접
  그래프 체이닝(끝점 격자 병합 → 차수≤2 성분 걷기)하는 방식으로 교체. 이 결정이
  나중에 NOMO의 구멍 난 스캔 대응(Slice 5)의 토대가 됐다.
- 별모양 프리즘 테스트에서 삼각분할 엔진 부재 → `mapbox-earcut` 의존성 추가.

## Slice 1 — Texel BodyScan, 첫 실데이터 허리둘레

**한 일**
- Texel BodyScan 다운로드(Yandex Disk 공개 API로 href 획득; 아카이브가 zip이 아니라
  **7z**였음 → Windows bsdtar로 해제).
- Part 1(10명) 구조 파악: `portal_mx`(전문 장비)와 `free_fusion`(단일 Kinect) 파이프라인이
  따로 있고, **portal_mx CSV에는 ISO 8559-1 조항 번호가 붙은 100+ 자동 치수**가 있었다.
  우리 6종이 전부 직접 매칭(m5/m102/m11/m1/m55/m3) — 기대 이상의 발견.
- 메시 규약 검증: portal_mx는 mm·Y-up·바닥0·watertight (키 1762.8mm ≈ Stature 176.4cm).
  free_fusion은 m 단위에 축 미검증 → **어댑터가 로드 거부** (추측 금지 원칙).
- 추정 허리 랜드마크(최소 몸통 둘레 탐색) 구현, 10명 전원 측정.

**우여곡절 — 첫 번째 정의 충돌**
첫 결과에서 m16 Waist Girth 대비 평균 −19.9mm의 계통 편차가 나왔다. 원인을 파보니
우리 정의(최소 둘레)와 정확히 일치하는 항목은 **m102 Minimum Waist Girth**였고, 그
기준으로는 평균 −3.5mm. m16(자연 허리선)과 m102의 20mm 차이는 알고리즘 오차가 아니라
**정의 차이**임이 수치로 증명됐다. 이후 "GT는 이름이 아니라 정의로 매핑한다"가
프로젝트 규칙이 됐고, 모든 데이터셋에 정의 대조표를 만든다(datasets.md).

또 하나: 두 파이프라인의 GT가 서로 크게 다르다(Man0 허리 102.7 vs 94.7cm — 다른
세션/장비). 비교는 반드시 같은 파이프라인의 메시 ↔ 같은 파이프라인의 CSV로만.

## Slice 2 — 가슴·목, 그리고 팔 간섭의 실체

**한 일**: 가슴(최대 둘레)·목(수평 v1 슬라이스) 추정 + 측정, Texel 10명 검증.

**우여곡절 — 3연속 반전**

1. **가슴 전원 실패.** 첫 구현에서 10명 전부 `chest_estimation_failed`. 겨드랑이를
   "아래에서 위로 3루프가 되는 최저 높이"로 찾았는데, 팔을 내린 자세에선 **손이
   엉덩이 높이에서 이미 몸통과 분리**돼 있어 손목 근처(0.55h)를 겨드랑이로 오인,
   가슴 탐색 창이 [허리, 그보다 아래] = 빈 창이 됐다. → **위에서 아래로** 탐색(3→1
   병합 전이점)으로 교체. 킥오프 메일 스레드에서 Zhen이 물었던 "팔 간섭" 문제의
   실데이터 버전이었다.
2. **여전히 −72mm 과소.** 프로파일을 직접 찍어보니 Man0는 팔이 몸에 붙은 이완
   자세라 **y≈1216mm에서 팔이 몸통에 병합**되는데 실제 가슴 높이(m42=1267mm)는 그
   위. 병합 위에서 둘레가 1418mm(팔 포함)로 튀니 탐색 창이 병합 아래에서 잘렸고,
   결과적으로 언더버스트를 재고 있었다(우리 값 1035.9 ≈ m18 Under Bust 1029 — 소름
   돋게 일치). → **병합 단면을 겨드랑이 높이의 몸통 폭으로 잘라내는**(직선 절단면 =
   겨드랑이를 가로지르는 줄자) tape 근사를 구현, 항상 `arm_clipped_at_merged_level`
   플래그. 평균 오차 −72 → **+33mm**, Woman4는 1114.1 vs GT 1114로 일치.
3. 목은 v1 수평 슬라이스가 m87(중간 목)이 아니라 **m11(목밑)에 더 가깝다**는 것도
   증거로 확인(+8.8 vs +26.7) — 예상과 반대였다.

## Slice 3 — 표면 경로 길이류, 어깨의 함정

**한 일**: edge-graph 최단경로 지오데식(`edge_graph_approximation` 명시), 등길이
(등목점→허리 표면 경로), 어깨너비(등목점 경유 강제), 소매길이(구간 합), 방향 검출
(발끝이 몸 축보다 앞 → facing).

**우여곡절 — +454mm 참사**
어깨점을 "겨드랑이 위 실루엣의 측면 극점"으로 잡았더니 어깨너비가 평균 +454mm.
팔을 내린 자세에서 그 극점은 어깨가 아니라 **팔 바깥면**이고, 지오데식이 팔 덩어리를
감아 돌았던 것. → 어깨점 = **겨드랑이 주름 (x,z) 기둥에서 수직으로 가장 높은 표면점**
(견봉 근사)으로 교체 → 평균 **+32mm**.

소매길이는 +197mm 계통 과대로 남았다(edge-graph 지그재그 + 견봉 근사 + 팔-몸통 접촉
우회 + ISO의 굽힌 팔 정의). 회귀 경계는 "더 나빠지지 않게"만 잡고, **개선 항목(heat
method, 팔 축 경유점)으로 공개 기록** — 숫자를 좋아 보이게 만들지 않는다는 원칙.

## Slice 4 — SMPL 두 트랙과 강건성 배터리

**한 일**
- SMPL v1.1.0(neutral, 300 shape PC) 도입. **chumpy가 최신 Python에 설치 자체가 안 됨**
  → 커스텀 Unpickler(chumpy 클래스 → 스텁, 배열은 `x` 속성에서 추출)로 pkl을 순수
  numpy로 1회 변환. 이후 smplx가 chumpy 없이 로드.
- 9개 체형 × T/A-pose 18개 신체 생성, sidecar JSON(시드·beta·포즈·모델 버전) 필수 기록.
- 강건성 배터리: yaw+이동 / 균일 스케일 / 정점 순열·winding 반전 / 노이즈 1mm /
  decimation 50·25% / 세분화 / **허리 방사 확장**(beta 단조성 검사를 계획 리뷰에서
  기각한 대체물).

**우여곡절 — 배터리가 잡아낸 실전 버그 2개 + 설계 교훈 2개**

1. **SMPL 허벅지 틈.** 중립 체형은 다리 사이가 떠 있어 허리 탐색이 허벅지 둘레
   (627mm)를 최소로 잡았다. Texel 피험자들은 허벅지가 붙어 있어 우연히 안 드러났던
   버그 → **가랑이 높이 검출**(축을 감싸는 루프가 처음 나타나는 높이) 추가.
2. **world-x 축 가정.** yaw 회전 테스트에서 가슴 +142mm 폭주. 팔 클리핑·어깨점·손목
   판정이 전부 world-x에 고정돼 있었다 — 실제 스캐너는 피험자 정렬을 보장하지
   않으므로 실전에서 터졌을 버그. 1차 수정(단면 PCA 주축)은 Woman4에서 다시 깨졌는데,
   **몸통 단면이 폭보다 깊으면 PCA가 전후 축을 잡기 때문**. 최종: **팔 루프 centroid
   연결선 = lateral 축**(팔은 정의상 몸 옆이므로 yaw 불변이며 항상 옳음), PCA는 폴백.
   수정 후 yaw 완전 불변 + Texel 정확도도 개선(가슴 +26.8, 어깨 +26.9).
3. **겨드랑이 지속성 3회 반복.** 노이즈 완화를 위해 "2연속 높이 지속" 조건을 넣었더니
   Woman4(분리 구간이 슬라이스 1개 두께)가 깨졌다. 지속 쌍을 우선하면 그녀의 진짜
   겨드랑이보다 아래의 두꺼운 팔뚝 분리 구간이 이겨버린다. 최종 설계: **위치는 항상
   최상단 분리 높이, 지속성은 신뢰도에만 반영**. 결과적으로 실스캔 1mm 노이즈에서
   가슴/어깨가 튀는 취약점은 남았고, 이는 감추지 않고 decisions.md #12에 공개 한계로
   기록했다(허리/목은 노이즈에 <12mm로 안정).
4. **허리 확장 검사의 정의 오류.** +10mm 확장 후 "허리둘레 +63mm"를 기대했는데
   +16mm만 나왔다 — 버그가 아니라 **최소둘레 정의의 올바른 동작**(최소값이 확장 밴드
   밖으로 이동). 검사를 "고정 높이에서의 둘레 증가"로 고치자 +50~58mm로 정상.

**T-pose 구현 간 비교 (synthetic_agreement)**
- SMPL-Anthropometry(MIT, DavidBoja)와 동일 vertex로 비교. 첫 시도에서 가슴 +2000mm —
  우리 estimated 랜드마크는 팔 내린 자세 전제라 T-pose 수평 팔에서 날개폭을 잰 것.
  버그가 아니라 **입력 계약 밖**. → 레퍼런스의 랜드마크 vertex 높이를 주입해 같은
  높이에서 측정하는 순수 기하 비교로 재설계.
- 최종: **허리 −1.1mm(최대 5.9), 가슴 −0.8mm(최대 18.5)** — 구현 간 사실상 일치.
  목 +24.3mm는 레퍼런스의 body-part 세그멘테이션(목 면만 슬라이스) 차이로 설명.

## Slice 5 — 데이터셋 확장과 검증 하네스

**데이터셋 조사에서 뒤집힌 것들**
- **3DPatBody**: 사전 조사에선 CC BY로 알려졌으나 논문 원문 확인 결과 **CC BY-NC-ND**,
  게다가 waist 정의가 **배꼽 높이**(우리 최소둘레와 불일치). 대규모 N 검증 가치가
  급락 → 5MB 샘플만 확보하고 보류.
- **HSRD-100**: 받아보니 **옷 입은 패션 스캔**(자켓·청바지·"폰 보는 자세"). 인체 치수
  GT 용도는 불가 → LOD 일관성(같은 기하, 다른 해상도) 검증 전용으로 용도 한정.
  Body-009 LOD1/LOD2 선별 다운로드 완료(스크립트는 후속 항목).
- **Texel Part 2**: 42명×5회라 반복성 프록시로 계획했으나 **메시가 아예 없음**(depth
  프레임만). 반복성 검증은 스캐너 도착 후로 사실상 전부 이연 — 계획서의 해당 항목을
  정직하게 수정했다.
- **NOMO-3D-400**: Zenodo에서 658MB 확보. TC2 치수 중 **NeckBase_Circ가 우리 목밑둘레
  정의와 정확히 일치**하는 귀중한 GT. waist는 Max/Trouser 변형뿐이라 GT 불가(aux).
  OBJ 단위는 피험자별 신장(Head_Top_Height)과 대조해 **검증** — 추측이 아니라.

**우여곡절 — 구멍 난 스캔**
NOMO 첫 실행에서 절반의 허리가 163~229mm(손목 둘레!). 스캔에 구멍이 많아 몸통
슬라이스가 열린 폴리라인이 되면, "닫힌 루프만 후보" 규칙 때문에 닫힌 **팔** 루프가
대신 뽑혔던 것. → 틈이 둘레의 20% 이하인 열린 루프를 후보에 포함하고 닫는 현(=구멍
위를 지나는 줄자)으로 측정, `gap_closed_open_loop` 플래그 필수. 7/10 정상화, 구멍이
큰 3건은 플래그가 붙은 채 후속 항목으로.

**검증 하네스**: `python -m body_measure validate` 한 줄로 4개 카테고리 리포트
(Texel·NOMO dataset_agreement / numerical_robustness / synthetic_agreement)를
`reports/`에 생성.

## 반복해서 작동한 원칙들

1. **정의가 계약** — 이름이 같아도 정의가 다르면 비교하지 않는다 (m16 vs m102, 배꼽
   허리, Adam's apple 목). spec과 대조표가 이를 강제.
2. **추측 금지** — 단위·축·정렬은 검증되거나 명시되거나 실패한다. free_fusion 거부,
   NOMO 신장 대조가 그 산물.
3. **숫자를 억지로 내지 않음** — 신뢰도 낮으면 null + 플래그. 모든 근사(클리핑,
   gap-closure, 견봉, edge-graph)는 quality 플래그로 하류까지 전파.
4. **검증이 설계를 고친다** — 강건성 배터리가 world-x 버그와 허벅지 틈 버그를,
   실데이터가 겨드랑이 방향·병합·구멍 문제를 각각 드러냈다. 6번의 주요 반전 모두
   테스트/리포트가 먼저 신호를 줬다.
5. **주장 범위 고정** — 어떤 수치도 카테고리 라벨 없이 보고되지 않는다.
